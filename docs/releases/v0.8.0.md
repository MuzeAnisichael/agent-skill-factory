## Reproduce

From a checkout with Python 3.10+:

```bash
python -m pip install -e .
python -m compileall -q src examples/skills tools
python -m unittest discover -s tests -v
python -m pip install build
python -m build
python tools/check_package.py --expected-version 0.8.0
```

The package check creates two temporary virtual environments and runs outside the source tree:
install -> dependency check -> version -> init -> generate -> strict lint -> eval draft -> eval ->
registry -> install -> resource inspection. Network access is required for build/runtime dependencies.

## Migration

- PyYAML is now a required small dependency; editable/wheel installs resolve it automatically.
- Schema-version-1 plans still load. Add `workflow`, `quality_checks` and optional complete `resource_files`.
- `--resources` creates directories but no longer adds fake helpers or templates.
- Old files are not deleted by `--force`; review obsolete placeholders manually. Strict lint flags them.
- YAML types and maximum lengths are enforced; quote versions and boolean-like metadata strings.
- Description repair preserves metadata values but can change comments and formatting.
- Codex UI strings now belong under `interface` in `agents/openai.yaml`.

See [Skill Output Format](../skill-output-format.md) for the plan contract and examples.

## What Has Not Been Proven

No live Ollama/API generation benchmark, first-party Agent runtime task benchmark or student user
trial was run. Package keyword tests do not prove routing quality. Dry-run scores can reflect
echoed instructions; repairs rerun the same assertions and are not held-out optimization.
The CSV helper tests demonstrate that helper's specified behavior, not broader Agent usefulness.

The core is not a sandbox, a hosted collaboration platform or a signed registry. The runtime
wheel intentionally excludes the examples; repository/source archives contain them.
GitHub release artifacts are provided, but there is no PyPI publication in this scope.
