# Python Code Review

## Workflow

1. 确认审查范围、预期行为和运行环境，阅读项目说明、改动及直接调用方；未提供差异时明确审查哪些文件。
2. 根据输入契约追踪边界条件、异常处理、数据类型和资源释放。需要领域检查清单时阅读 `references/checklist.md`。
3. 对疑似问题给出最小复现输入；有可用且获准执行的测试环境时运行相关测试，不把静态推断写成已运行结果。
4. 按影响排序报告问题，包含文件与行号、触发条件、实际和预期行为、修复建议及回归测试。没有可证实的问题时明确说明，并列出未验证部分。

## Constraints

- 以缺陷和行为回归为主，不把个人风格偏好当成错误。
- 不修改代码、不安装依赖、不连接外部服务，除非用户授权这些操作。
- 不因缺少测试就推断代码必然有错；区分已复现、静态证据和待确认假设。

## Quality Checks

- 每条问题都提供可追溯的位置和具体触发条件。
- 标注实际执行过的测试、结果及未运行的原因；不编造覆盖率。
- 建议的回归测试能区分修复前后行为，且不改变任务范围。
